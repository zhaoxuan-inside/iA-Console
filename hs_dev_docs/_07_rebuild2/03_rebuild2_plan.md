## 1. 设计原则（按功能重新设计的四条硬规）

1. **单执行模型**：产品里只有一个「命令执行」概念。终端面直敲与输入行提交都必须流经同一判定点（风险闸门→确认升级→账本）。不再存在「有闸门的路径」和「没闸门的路径」。
2. **单一事实源**：方法表、内置命令映射、IPC 客户端、主题令牌、确认状态机、会话状态——每样一份，前端只做呈现。
3. **核心运行时 + 薄前端**：GUI/CLI/TUI/MCP 是同一运行时的四种壳；Q4「双形态行为绝对一致」从口号变为架构约束（共享 crate 强制）。
4. **可证实验收**：02 缺陷登记的每一条，重建后要么关闭、要么在 PRD 显式裁定不继承；假象功能（S0）零容忍。

## 3. 新功能架构（草案，详设阶段细化）

```
ia-runtime（新核心 crate，替代现 core 前端耦合面）
  ├─ session 作用域：会话是唯一上下文容器（cwd/env/对话轨/历史段）
  ├─ 执行引擎：唯一入口 execute(request, origin)
  │    origin ∈ {TerminalPane, InputLine, Agent}   ← 终端面成为一等公民
  │    流程：风险判定（静态+AI 合成）→ 闸门决策 → 确认升级（单一状态机，事件驱动）
  │         → 执行（PTY 或进程）→ 账本（全量输出+回滚捕获）→ 事件流
  ├─ 闸门呈现协议：runtime 只发 GateDecision 事件；「弱提醒/二次Enter/确认词」由前端按同一协议渲染
  └─ 内置命令单表（ia-*），前端零本地展开

ia-shell-integ（受控 shell 升级）
  └─ 事件侧信道（Q54 地基）扩展为双向：命令事件上行 + 闸门裁决下行
     （zle accept-line 拦截：危险命令 Enter 后终端内弱提醒，与 Q35 直输语义对齐）

前端（薄壳）：iac-gui / iac(CLI) / iacd(MCP) —— 只保留视口、键位、渲染；逻辑一律入 runtime
```
