### Q15. 域 1 主成功流（1/3）：输入分流规则

- **题域**：核心交互 / 输入分流
- **题干**：主输入行直驱（Q7 A）下如何区分「直接命令」与「自然语言意图」（如「ls -la」直接执行；「找出当前目录下最大的 10 个文件」走 AI 提案）。
- **选项（3）与利弊**：
  - A：混合识别（推荐）——自然语言特征（中文/句式）自动走 AI；命令形态（首 token 已知命令/可执行路径）直接执行；`??` 强制 AI、`\` 强制字面。零学习成本、老手零打扰；英文歧义串需定优先规则且可纠正。
  - B：显式前缀——一律 `??` 唤起 AI，其余当命令；零歧义但初学者须先学标记。
  - C：模式切换（Tab 切 AI/命令）——明确但有模式认知负担。
- **开发者答复**：A —— 混合识别
- **采纳决策**：CONFIRMED——分流规则 = **混合识别**：自然语言特征自动走 AI；命令形态（首 token 已知命令/可执行路径）直接执行；`??` 强制 AI、`\` 强制字面。**细则待钉**：英文歧义串（find/make 等）的命令优先规则；误判纠正方式（如「未找到该命令 → 是否让 AI 帮忙？」）；命令存在性检查边界（PATH 探测成本）。
- **关联落盘**：PRD 骨架 §2（域 1）；域 13（标记语言）走查联动。

- **题干**：混合识别（Q15）必然有误判——自然语言被当成命令（→ command not found），或英文歧义串（find/make 等）被当成直接命令。纠正时机与方式？
- **选项（3）与利弊**：
  - A：失败兜底 + 一键转 AI（推荐）——执行失败（command not found / 非零退出）时就地提示「要不要 AI 帮忙？」，一键转提案；不前置打断，成本最低、老手零打扰；误判只能在失败后暴露，依赖失败检测准确性。
  - B：歧义前置询问——歧义串执行前先问「直接执行 / 问 AI」；最准确，但老手每次多一步打断。
  - C：A + 纠正学习——记录「误判→纠正」对，同类输入下次自动走纠正后路径；最聪明，但需持久化与防错误学习机制。
- **开发者答复**：A —— 失败兜底 + 一键转 AI
- **采纳决策**：CONFIRMED——误判纠正 = **执行后失败兜底**：命令执行失败（command not found / 非零退出）时，在输出尾部就地提示「要不要 AI 帮忙？」，一键以同一输入转 AI 提案路径；不做执行前歧义拦截。细则钉定：纠错触发点为**执行后检测**（exit code），非执行前 PATH 探测（避免探测成本与漏判）；Q15 英文歧义串默认按命令形态直接执行，误判经本兜底纠正。
- **关联落盘**：PRD 骨架 §1/§2（域 1）；域 3（错误医生）走查联动——兜底入口与失败诊断共用触发点。
