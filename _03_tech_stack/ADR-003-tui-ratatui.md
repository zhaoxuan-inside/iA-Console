# ADR-003-TUI 选 ratatui + crossterm（_03_tech_stack）

> 状态：accepted　日期：2026-10-11

## 背景

G4 要求 TUI 同屏 AI 对话与提案确认执行（AC-09），前端形态为"嵌入现有终端的伴生界面"，非独立 GUI。ADR-001 已定 Rust。

## 决策

TUI 选定 **ratatui**（渲染）+ **crossterm**（跨平台终端事件/原始模式）。

## 理由

- Rust TUI 事实标准（fork 自停更的 tui-rs，社区活跃），即时模式渲染适合"提案卡 + 对话流 + 历史列表"多面板布局。
- crossterm 一套 API 覆盖 Unix/Windows 终端事件与样式，符合三平台目标。
- 纯 Rust 无系统依赖，随单二进制分发。

## 备选方案

| 方案 | 未选原因 |
|---|---|
| tui-rs | 已停止维护 |
| egui | 即时模式 GUI，需 OpenGL/wgpu 上下文，与终端伴生定位不符 |
| Bubbletea | Go 生态，与 ADR-001 冲突 |

## 后果

- 正面：布局/组件能力开箱即用，焦点管理、滚动、文本换行均有现成组件。
- 负面/代价：0.x 版本 API 仍可能破坏性变更（锁 minor，升级走专项）；大输出列表需自行虚拟化渲染。
- 对 _04 设计的影响：TUI 全部组件按 UI 豁免规则不入 _07，可复用逻辑（提案渲染数据组装、确认流）下沉 core 五段方法；TUI 仅为 IPC 客户端，不持业务状态。
